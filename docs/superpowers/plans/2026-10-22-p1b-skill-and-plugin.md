# BSV AI DevKit phase 1b: `bsv-dev-skill` 0.1.0 and the Claude Code plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `bsv-dev-skill` 0.1.0 under `packages/skill`: an Agent-Skills-spec `SKILL.md` with the phase-1 reference files, scripts and assets, the `/bsv-review` and `/bsv-design` commands, a Claude Code plugin manifest that bundles both MCPs, a marketplace at the repo root and at `packages/skill`, trigger tests, validation in CI, and the release zip.

**Architecture:** `packages/skill` is the plugin root (`.claude-plugin/plugin.json`, `commands/`, `skills/bsv-dev/`); the repo root carries `.claude-plugin/marketplace.json` pointing at `./packages/skill` so `claude plugin marketplace add bsv-blockchain/bsv-mcp` and `npx skills add bsv-blockchain/bsv-mcp` both find the skill. Judgment files are authored in `skills/bsv-dev/references/`; `facts.md`, `guardrails.md`, `stack.md`, `custody-shapes.md`, `threat-model.md` are generated by `pnpm sync` (plan 1a Task 4) and never edited by hand. The skill instructs and prints commands; it never edits agent configuration.

**Tech Stack:** Markdown + YAML frontmatter (Agent Skills spec), `skills-ref` 0.1.5 (`npx skills-ref validate`), Claude Code `claude plugin validate --strict`, bash scripts (`curl`, `jq` optional), `vitest` for trigger and structure tests, `zip` in `release.yml`.

**Spec:** `docs/superpowers/specs/2026-10-22-bsv-ai-devkit-design.md` (§3 constraints, §4 "Why the plugin root is packages/skill", §6 all subsections, §9 CI/release). Source lessons (LOCAL, never committed): the playbook and the handoff; each reference task names the sections to read. Everything written must stand alone (no private paths, no quoted chat). Plan 1a (`docs/superpowers/plans/2026-10-22-p1a-foundation-and-mcp.md`) defines the content schema, sync outputs, tool names, env var names and CI job names used here; this plan does not redefine them.

## Global Constraints

- Branch `feat/bsv-ai-devkit-p1` (continues plan 1a); every task ends with a commit ending in `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Public, MIT, no code from the earlier apps, no private keys anywhere; the skill never asks for, generates for production, or stores private keys or recovery phrases.
- Agent Skills spec: `name` ≤64 chars, lowercase/digits/hyphens, equals the directory name (`bsv-dev`); `description` ≤1024 chars; `compatibility` ≤500; `metadata` string→string; `SKILL.md` body ≤500 lines (target ≤250); references one level deep (`references/<file>.md`, never `references/a/b.md`); `skills-ref validate` passes.
- Plugin: `packages/skill/.claude-plugin/plugin.json` `name "bsv-dev"`, `version "0.1.0"`, every component path starts with `./`; marketplace `name "bsv"` (so the install id is `bsv-dev@bsv`); neither name may read as Anthropic's (no `claude`/`anthropic` in names). `claude plugin validate --strict` passes on `packages/skill` and on the repo root.
- MCP bundle (spec §6.3a): `bsv-mcp` = `{"command":"npx","args":["-y","@bsv/mcp@2.0.0"],"env":{"BSV_NETWORK":"${user_config.bsv_network}","ARCADE_URL":"${user_config.arcade_url}"}}`; `bsv-docs` = `{"type":"http","url":"https://bsv.writedocs.io/mcp"}`. `userConfig` exposes `bsv_network` (string, options `testnet`/`mainnet`, default `testnet`) and `arcade_url` (string, optional, default `""`). `BSV_MCP_ALLOW_MAINNET_BROADCAST` is never in `userConfig`. Nothing uses `${CLAUDE_PLUGIN_ROOT}` for the MCP.
- Skill `metadata.version` `"0.1.0"` and `metadata.facts-from` `"@bsv/mcp 2.0.0"` move together with the MCP version through the tag release.
- Default decisions the skill states (spec §6.1): BRC-100 wallet always; explicit custody shape; Arcade for every broadcast and txid read; final at `SEEN_ON_NETWORK`+ with no competitor, never `MINED`; Rúnar from upstream main never npm 0.4.x; 1Color for tokens; `@bsv/sdk` 3.x `WalletClient('auto', originator)`; `@bsv/simple` only per `simple-routing.md`; testnet default, mainnet only by explicit `BSV_NETWORK=mainnet`; fees from the serialized draft.
- Anti-goal grep (plan 1a `scripts/anti-goals.sh`) runs over `packages/skill/skills`: forbidden phrasings may appear only on lines that say never/not/don't.
- Install strings (exact): `npx skills add bsv-blockchain/bsv-mcp`; `claude plugin marketplace add bsv-blockchain/bsv-mcp && claude plugin install bsv-dev@bsv`; `claude mcp add --transport http bsv-docs https://bsv.writedocs.io/mcp`; `claude mcp add bsv-mcp -e BSV_NETWORK=testnet -- npx -y @bsv/mcp`.

## Review Focus

1. A prompt that mentions BSV only as noise ("my BSV app is written in Solana's Anchor, port it to Solana") must not fire the skill; the keyword matcher scores quoted trigger phrases, not the bare word "BSV" (Task 6 test `solana prompts are ignored even with bsv noise`).
2. `scripts/network-guard.sh` with `BSV_NETWORK` unset must exit 0 and print `testnet` (the default), not fail: apps call it at boot before `.env` loading in some setups (Task 3 test `unset network defaults to testnet`).
3. `scripts/arcade-check.sh` against a txid the instance never saw (404) must print `verdict: no-verdict` and exit 0, not a curl error (Task 3 test `404 prints no-verdict`).
4. `claude plugin install bsv-dev@bsv` on a machine without the `claude` CLI's optional `${user_config.arcade_url}` set: an empty `ARCADE_URL` must be tolerated by `@bsv/mcp` (plan 1a `loadConfig` treats `""` as unset; Task 5 test `empty arcade_url resolves to the network default` pins it here through the plugin's env mapping).
5. `references/*.md` linked from the routing table but missing from disk (a rename): the structure test must fail the build (Task 6 test `every routing-table target exists and every reference is routed`).
